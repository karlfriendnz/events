End-to-end HTTP path — proven ✅

The seam was verified through a live Nitro dev server (port 3077, pointed at MySQL), not just the repo layer: GET /api/v1/organisations → route → repo → MySQL → contract-validated JSON returned the seeded org; GET /api/v1/people?orgId=… returned its roster; a missing orgId correctly returned 400. The full request path (Nitro route → repository → Drizzle → MySQL → parse-on-output) works.

Security check & penetration test

Static review + a live read-only probe against MySQL. Full report: docs/security-audit.md. The mapping layer (parameterised queries, Zod in/out, secrets kept server-side) is sound; the missing piece is the authn/authz layer, which the backend team owns. Two cheap, backend-independent findings were fixed in place.

FindingDetailStatus
CRITICAL-1No auth on any /api/v1 route
Backend team owns the authn layer — the seam is deliberately the data-mapping layer; documented as #1 priority for handover.		⚠ handover
CRITICAL-2No tenant isolation (orgId is a trusted param)
Needs the session-derived requireOrgAccess() gate — backend team, alongside CRIT-1.		⚠ handover
CRITICAL-3Mass-assignment: records/orgs movable between tenants
Fixed now. Patch contracts strip orgId/parentId; repos no longer write them.		✅ fixed
HIGH-1Unbounded list endpoints
Flagged for the backend team — add default+max page size on every list route.		⚠ handover
MEDIUM-1/2Error leakage · anon hierarchy enumeration
Covered by the global error handler + the auth gate (backend team).		⚠ handover
LOW-1Hardcoded root DB fallback
Fixed now. Production throws if MYSQL_URL is unset; no root fallback ships.		✅ fixed
